# pypto4A8 适配问题笔记

设计笔记 · 2026-11-11

[Workload 方案](a8-plan.md)围绕目标适配、CPU 解释执行和计时回放展开。
下面这些问题决定接下来如何实现。

## 1. 为早期 Tile IR 定义目标含义

矩阵乘 IR 已带有 `Mat/Acc` 存储和执行角色标注。
需要先确定最小 PE 配置：输入、累加器和输出分别存在哪里，
各操作接受哪些存储类别，以及存储之间需要哪些搬运或布局转换。

第一版适配应为 load、store、matmul、matmul_acc 建立可追溯的映射，
明确支持的 dtype、shape 和有效范围。这也决定了首个 workload 的预期操作数量。

## 2. 让解释执行完整保留数据关系

解释器需要处理标量运算、循环、循环携带变量、分支和 tile 功能计算。
分支读取 tile 结果时，记录阶段需要取得该结果的实际值。

关键在于对象身份：视图与源对象共享存储，累加同时涉及读取和写入，
同一个地址复用后可能对应新一代对象。Trace 要保留这些关系和实际访问范围。
首批测试应覆盖累加、重叠视图、带 stride/尾块的访问，以及地址复用。

## 3. 把 tile 操作变成可计时的工作

PE 配置需要确定调度窗口和队列容量、发射规则、Cube/Vector/访存资源、
tile 存储容量及释放策略。操作代价需要根据 shape 和 dtype 给出延迟、
启动间隔、传输字节量和带宽占用。

回放时结合生产者依赖和存储重叠造成的冲突决定调度。
用几个小例子验证独立操作重叠、累加链停顿、访存竞争和容量反压。
数值参考与计时检查分别验证功能和性能行为。

## 4. 从单 PE 扩展到多 PE

多 PE 需要逐线程 trace、放置关系、显式同步和共享资源预算。
回放根据数据与同步依赖确定跨线程顺序。起步 workload 采用执行路径确定、
同步关系明确的程序。

WSE 的计算吞吐和带宽数值是整核预算。配置中需要明确这些预算如何分配到各 PE，
以及哪些资源由多个 PE 共享。

## 5. 为 WSE 通信补充显式契约

Calendar 传输需要在 tile trace 旁附带通信描述：

| 部分 | 需要确定的信息 |
| ---- | -------------- |
| 参与者与放置 | 集合类型、组、source/root、归约操作、节点映射，以及每节点一个通信 owner |
| 路由与时隙服务 | 逐 source 的 `routeBits`、逻辑 key、`keyId`、`opcode`，以及匹配的 `CalReg` 镜像和版本 |
| 存储几何 | 对称 arena、source 的 `selfOff`、行数、行字节、stride、目标范围和容量 |
| 传输身份 | Launch、epoch、source/segment 身份、去重，以及复用前的排空规则 |
| 完成条件 | 计入 `expVal` 的唯一且已提交远端有效字节、本地自拷贝覆盖、写可见性和目的对象发布 |

当前白皮书要求的顺序是：准备源数据，登记接收并预留资源，准备有界发送服务，
集合参与者对齐，发送，最后收集排空和写完成证据并发布目的对象。
接收登记与数据到达分别完成，从而允许等待接收期间继续推进发送。
源和目的对象的代际分别保留到对应传输责任结束。

适配器需要定义这些事件及其依赖，并确定排空边界上的计划装载和重配置流程。
用一个小规模集合通信例子验证路由、字节计量、多轮 epoch 和消费者就绪条件。

## 6. 对接带计时的 WSE 模型

现有 `wse-model` 的 NoC 实现提供路由和字节计量。
性能回放还需要 Calendar 放行时间、链路/端口服务、缓冲、反压、接收写入带宽和时钟域换算。

目标配置还需确定几项架构选择：40/48 节点拓扑及路由位宽、local SRAM 的地址/bank/端口，
以及它与核内存储模型的衔接。白皮书决策 0007 确定了采用 superscalarNPU 的方向，
可执行模型的迁移是后续集成工作。
